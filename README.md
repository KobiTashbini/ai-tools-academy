# AI TOOLS Academy

פלטפורמת ידע בעברית. השלב הנוכחי כולל בית, אטלס 12 קטגוריות ו־35 פריטי לימוד עם הסברים, דוגמאות, תרגילים, מקורות ותאריכי בדיקה. אין קטגוריות ריקות. חיפוש והשוואה עדיין אינם ממומשים.

בקטגוריות מופיעה טבלת כלים עם מיון, הרחבת שורה ומעבר לכרטיסיות. [הגדרות המדדים ומקורותיהם](docs/knowledge/METRICS.md): נתוני GitHub הם צילום מצב מתוארך. GitHub Interest הוא מדד עניין קהילתי מקומי לפי Stars ו־Forks, ולא מדד איכות או נתח שוק.

כל הקטגוריות משתמשות בטבלה קומפקטית עם שש עמודות. לכל פריט מופיעה ״חשיבות ללימוד״ עם עדיפות והנמקה; זו המלצה פדגוגית, לא נתון תפוצה. GitHub Interest זמין דרך ״עמודות נוספות״ ובהרחבה. מדגם שבעת מאגרי קטגוריה 02 נשמר מה־[פיילוט](docs/knowledge/CATEGORY_02_PILOT.md); קטגוריה 08 כוללת מדגם נפרד של Ollama, llama.cpp ו־vLLM. אין להשוות ציונים בין המדגמים.

ללמידה: מתחילים באטלס, בתחום 00, בפרק יסודות מודלי השפה. [מפת כיסוי וסדר קריאה](docs/knowledge/CONTENT_COVERAGE.md) מפרטת מה זמין ומה עוד נותר.

## הפעלה מקומית

נדרש Node.js 24 LTS עם npm. מתוך תיקיית הפרויקט:

```powershell
npm ci
npm run dev
```

פותחים http://localhost:3000 . עוצרים עם Ctrl+C. אין צורך ב־env, במפתחות או במסד נתונים.

## רענון נתוני GitHub



```powershell
npm run metrics:refresh
npm test
npm run build
npm run start
```

הרענון הידני דורש רשת וניגש ל־GitHub API הציבורי ללא אסימון. הוא מעדכן רק את שלושת מנועי ההסקה במדגם 08, כולל Stars, Forks ו־Commit אחרון. רק אחרי הצלחת כל קריאות האיסוף נשמר צילום מצב חדש. יש לעצור שרת Production קודם לפני בנייה ולהפעיל אותו מחדש אחריה. בדוק את השינויים לפני Commit או פרסום.

פתיחת האתר אינה מרעננת נתונים ואין כרגע רענון מתוזמן. תאריכי השקה נבדקים ממקורות בנפרד, ואינם נגזרים מתאריך יצירת מאגר. אוטומציה עתידית יכולה לשמור מטמון אחרון תקין ומועד עדכון גלוי, אך לא הוקמה תשתית כזו.

## ניפוי שגיאות בצד השרת

עמודי `src/app/atlas/page.tsx` ו־`src/app/atlas/[categoryId]/page.tsx` הם Server Components: פקודות `debugger;` בהם דורשות Debugger שמחובר ל־Node.js, ולא רק DevTools של לשונית האתר.

יש לפתוח ב־VS Code את תיקיית `AI TOOLS` המלאה, ולא את `src` בלבד, כדי שיזהה את `.vscode/launch.json` ואת `tsconfig.json`. מצב Debug משתמש ב־Webpack בעקבות שגיאה פנימית שנצפתה ב־Turbopack; ההפעלה הרגילה נשארת עם ברירת המחדל של Next.js.

- ב־VS Code: עוצרים את שרת הפיתוח הקודם, פותחים Run and Debug, בוחרים `Next.js: debug server` ולוחצים F5. לאחר שהשרת מוכן פותחים או מרעננים את `/atlas` או `/atlas/02`. העצירה והמשתנים יוצגו בעורך.
- דרך Chrome: מפעילים `npm run dev:debug`, פותחים `chrome://inspect`, מגדירים ב־Configure את `localhost:9230` ופותחים Inspect של שרת Next.js. משאירים חלון זה פתוח ומרעננים את עמוד האתר. ממשיכים באמצעות F8.

יש לוודא שב־Debugger לא מופעל Deactivate breakpoints. פקודה ברמת המודול נעצרת רק כשהמודול נטען; פקודה בתוך פונקציית העמוד נעצרת כשהעמוד מרונדר בשרת. ב־Production העמודים נוצרים סטטית בעת build, ולכן משתמשים בשרת הפיתוח לבדיקה זו. פורט ה־Inspector נפתח במפורש במחשב המקומי בלבד. הוראות תואמות ל־[תיעוד Next.js](https://nextjs.org/docs/app/guides/debugging).

## בדיקות

`next-env.d.ts` הוא קובץ טיפוסים אוטומטי שאינו נשמר ב־Git. פקודת `typecheck` מפעילה `next typegen` לפני TypeScript כדי ליצור אותו ואת טיפוסי הנתיבים גם לאחר Clone חדש; `dev` ו־`build` יוצרים אותם אף הם.

```powershell
npm run typecheck
npm test
npm run build
npm run start
```

יש לעצור שרת dev לפני הפעלת start באותו פורט. build אינו בדיקה חזותית. לבדיקה ידנית: ניווט לבית ולאטלס, קישור ״איך נלמד״, מקלדת Tab וקישור דילוג לתוכן, תצוגת טלפון, עברית ושמות באנגלית ללא גלישה אופקית.

בחלון נוסף, כשהשרת פועל: `npm run test:smoke`. הבדיקה מכסה את הבית, האטלס, 12 הקטגוריות, MCP ונתיבים חסרים. לפורט אחר מגדירים `SMOKE_BASE_URL`.

## מבנה התוכן

`content/categories.json` שומר את הטקסונומיה הקבועה; `content/entries.json` ו־`content/lessons.json` שומרים תוכן ומקורות. `src/domain/knowledge.ts` מגדיר טיפוסים, ו־`src/data/knowledge.ts` מספק גישה לתוכן מפורסם בלבד. בדיקת תקינות מופעלת בזמן טעינת הנתונים; תוכן פגום מכשיל את הבנייה. המודל טרם פוצל למסמכי Markdown ולראיות ברמת כל טענה.
