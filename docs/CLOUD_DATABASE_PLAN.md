# תוכנית מסד נתונים בענן

תאריך: 2026-10-31. עדכון: הוקם פרויקט Supabase, הייבוא הושלם, והמבנה נורמל לפי D-026 ומיגרציות 002–004. האתר טרם חובר. מסמך זה הוא תוכנית המעבר המקורית; מפת השדות בפועל ב־database/DATA_DICTIONARY.md, הוראות ב־database/README.md ומצב עדכני ב־PROJECT_STATUS.md. סעיפי הצעה להלן הם רקע היסטורי ואינם בקשת אישור מחודשת לפעולות שכבר אושרו ובוצעו.

## הצעה לאישור
פרויקט Supabase נפרד בשם ai-tools-academy, על PostgreSQL. לבדוק תחילה את הארגון, המסלול, מכסת הפרויקטים ואזור האירוח הזמינים בחשבון. להתחיל בחינם רק אם החשבון מאפשר זאת, ללא שדרוג מסלול או חיוב ללא אישור. לא לשתף בסיס, מפתחות או הרשאות עם LinguaReader. חלופת PostgreSQL מנוהל אצל ספק אחר נשארת אפשרית; אין כעת צורך בשרת ASP.NET Core נוסף.

## מודל לוגי מוצע
| ישות | תוכן וקשרים |
|---|---|
| categories | 12 מזהי 00–11, שמות ותיאורים |
| entries | מזהה ו־slug ייחודיים, סוג, תקציר, מצב פרסום ואימות ותאריכי הוספה/אישור |
| entry_categories | קשר רבים לרבים, ללא הכפלת כלי |
| entry_revisions | גרסה מלאה של התוכן, סיבת שינוי, סעיפים מסודרים, דוגמאות ותרגילים; תוכן מובנה ב־JSONB לפי צורך |
| entry_relations | קישורי פריטים, דרישות קשר תקינות |
| sources / revision_sources | כתובת מקור, טענה נתמכת ותאריך בדיקה לכל גרסה |
| learning_guidance | עדיפות, הנמקה ומועד סקירה לכל פריט |
| tool_facts / language_support | עובדות, דיוק תאריך השקה, סוג תמיכה ושפות עם מקורות |
| repositories / repository_snapshots | זהות מאגר ומדידות מתוארכות של Stars, Forks ופעילות |
| metric_samples / sample_members / metric_observations | נוסחה וגרסתה, חברי המדגם ותוצאות; שמירת מדגמי 02 ו־08 בנפרד |
| category_guides / catalog_presentation | מדריכי קריאה והגדרות הצגה קיימות |
| research_proposals / proposal_decisions | לפני/אחרי, מקורות ואישור; ללא פרסום אוטומטי |
| import_batches / import_documents | מזהה ייבוא, נתיב מקור, hash והעתק JSON מקורי לצורך התאמה ושימור שדות |

זהו מודל לוגי לסקירה, לא סכמת SQL שבוצעה. 35 הרשומות כוללות גם מושגים ופרוטוקולים, ולכן שם הישות entries ולא רק tools. אין להמציא היסטוריית גרסאות או מדידות שלא קיימת בקבצים.

## מעבר וחיבור האתר
1. למפות כל שדה בכל קובצי content ובתור research; מסמכי docs נשארים תיעוד בפרויקט, ולא מתפרסמים אוטומטית כתוכן.
2. להכין migration וייבוא חוזר בטוח, עם מפתחות קבועים, אילוצי ייחודיות, מפתחות זרים וטרנזקציה. ייבוא חוזר אינו מוחק או דורס עדכוני ענן בשקט.
3. לבדוק מקומית את המיפוי, כל 35 הפריטים, 12 הקטגוריות, המקורות, המדדים והקשרים. לשמר גם שדות מקור שלא נורמלו.
4. לאחר אישור יצירת משאב וחיבור מאובטח, להחיל schema ולייבא לפרויקט החדש; להשוות ספירות ותוכן מלא מול המקור ולבדוק שאפשר לשחזר.
5. בתחילה להשאיר את האתר על JSON. בשלב החלפה מפורש, להפוך את המסד למקור האמת ולייצא ממנו צילום מצב מאומת לבנייה סטטית. להימנע משני מקורות עריכה פעילים. אין צורך בקריאת DB מכל דפדפן.
6. לאחר החלפת המקור להתאים את רענון המדדים ותהליך החלת הצעות המחקר. מחקר ימשיך ליצור הצעות בלבד; פרסום דורש אישור אנושי. עד אז הנהלים הנוכחיים נשארים בתוקף.

## הרשאות, תפעול ודרך חזרה
RLS והרשאות מזעריות; אין כתיבה אנונימית. תור המחקר וראיות אישור אינם ציבוריים. זהות קריאה לבנייה תראה תוכן מאושר בלבד, וזהות הייבוא נפרדת ומוגבלת. מפתחות נשמרים רק בהגדרות מקומיות/שרת מאובטחות, ללא ערכים בצ'אט, במסמכים או ב־Git. לפני החלפה לשמור את המקור המקורי וייצוא עצמאי מהמסד. כשל במשיכת נתונים לא יפרסם קטלוג חלקי; האתר הקודם יישאר עד בנייה תקינה. גיבויים, בדיקת שחזור ותזמון אוטומטי דורשים מימוש נפרד; לא הוקמו בסבב זה.
