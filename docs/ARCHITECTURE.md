## המימוש הנוכחי
פרויקט Supabase ai-tools-academy (winnpnsmwkullbhrolan) פעיל במסלול Free, באזור eu-west-3. מיגרציות 002–004 יצרו בסכמה academy מבנה מנורמל עם שדות מפורשים וקשרים: פריטים, תוכן וסעיפים, מקורות, קטגוריות, המלצות, שפות, השקות, מאגרים ומדידות, מדגמי עניין, מדדי חבילות, מדריכים והצעות. אין payload או עמודות JSON בטבלאות הפעילות. אין שני עותקים פעילים של עדיפות, מקורות או תיאור קטלוג.

catalog הוא View לקריאה נוחה; entry_documents מרכיב JSON לייצוא ולבדיקת התאמה בלבד; community_interest מחשב ציונים מכל מדגם ומועד. ה־Views אינם מאחסנים עותק תוכן נוסף וכולם security_invoker. RLS מופעל בכל הטבלאות, ללא policies ציבוריות או חשיפת schema ל־API.

academy_import_archive שומרת את מבנה הייבוא הקודם ואת נוסחי הקטלוג שהוחלפו כצילום היסטורי מוגן מכתיבה. אין FK מהארכיון לטבלאות הפעילות. זה אינו גיבוי חיצוני או מקור לעריכה. revision מתאר את גרסת הפריט הנוכחית; אין מערכת audit לשינויים עתידיים לפני הקמת עריכה מקוונת. השוואה מלאה למקור ובדיקות הרשאות ודרך חזרה עברו מקומית; לאחר ההחלה אומתו גם ספירות, תוכן, חתימות ו־RLS בענן. פירוט ב־[מפת הנתונים](../database/DATA_DICTIONARY.md) וב־[הוראות המסד](../database/README.md).

האתר עדיין נבנה מקובצי JSON ואינו מחובר למסד. גם המחקר ורענון המדדים עדיין פועלים בקבצים. זהות קריאה מוגבלת, מעבר מקור האמת, התאמת תהליכי הכתיבה וגיבוי חיצוני/שחזור הם עבודה עתידית. ההרשאה הקיימת אינה כוללת פריסה או חיוב.

מחקר מתוזמן מתבצע מחוץ לאפליקציה באמצעות אוטומציה מקומית של Codex (ai-tools-academy), עם כתיבה מוגבלת לתיקיית research בלבד. התור אינו נטען בקטלוג ואינו נחשף בנתיבי האתר. validateProposals ו־research:check בודקים מקורות, זהויות ומצבי אישור; אישור בצ'אט והחלה הם שלב נפרד. אין API לעריכה מקוונת או פרסום אוטומטי. addedAt הוא תאריך הוספה נפרד מתאריך השקת המוצר; הוא מוצג בעמוד כלי ובעמודה אופציונלית עם מיון. הוולידציה דורשת ראיות החלטה ותאריכי גילוי/אישור עבור הוספה עתידית מהצעה. פרוטוקול המחקר ב־docs/knowledge/WEEKLY_RESEARCH.md.
הקטלוג מציג המלצת לימוד והנמקה בכל שורה ובכרטיסיות, מתוך learningPriority שבפרק ו־`content/learning-guidance.json`. ה־Loader דורש הנמקה לכל פריט; נתוני GitHub אינם תנאי להצגת ההמלצה. GitHub Interest עבר לעמודה לבחירה ונשמר בפירוט. אין נתון שימוש חדש או שירות נוסף.
`npm run metrics:refresh` מבצע איסוף ידני דרך GitHub REST הציבורי לשלושת מנועי ההסקה שבמדגם 08. תוצאות נכתבות רק לאחר שכל הקריאות הצליחו ל־`github-snapshot.json` ול־`inference-community-interest.json`; שכבת הנתונים מאמתת התאמה בין שני הקבצים ומחשבת מדד יחסי נפרד ממדגם 02. כדי לפרסם את צילום המצב נדרשת בנייה חדשה. פתיחת האתר אינה מפעילה איסוף. רענון מתוזמן עם מטמון הוא אפשרות להמשך ולא מומש.
התוכן כולל כעת 35 פריטי לימוד; מדריכי הקריאה לקטגוריות 07 ו־08 נמצאים ב־`content/category-guides.json` ומוצגים בעמוד הקטגוריה עם קישורים לפרקים. אלה נתונים סטטיים ללא תלות, שירות או קריאת מודל נוספת. משפחות מודלים משתמשות בסוג model הקיים; פלטפורמות גישה/ענן בסוג platform, ומנועי הסקה בסוג runtime.
קובץ `next-env.d.ts` וטיפוסי הנתיבים נוצרים אוטומטית ואינם מנוהלים ב־Git. פקודת `typecheck` מייצרת אותם באמצעות `next typegen` לפני הפעלת TypeScript.

סביבת הפיתוח כוללת הפעלת Debug אופציונלית עם Webpack לשרת Node.js דרך `npm run dev:debug` והגדרת F5 ב־VS Code. עמודי האטלס נשארים Server Components; ניפוי קוד שרת דורש חיבור ל־Inspector המקומי, בנפרד מ־DevTools של לשונית האתר. הוראות ב־README.

תצוגת רשימת כלים בכל קטגוריה משתמשת ב־ToolCatalog משותף: טבלה כברירת מחדל, כרטיסיות אופציונליות, מיון והרחבה מקומית באמצעות React state. עובדות טבלה ו־GitHub נשמרות כצילום מצב JSON ונבדקות בטעינה. אין קריאות לספקים מתוך הדפדפן; מקור ושיטת המדידה מפורטים ב־[METRICS.md](knowledge/METRICS.md).

Next.js + React + TypeScript, תוכן JSON מקומי תחילה, ללא קריאת מסד בזמן הריצה או API נוסף. עמודים נוצרים סטטית בעת build. src/domain מגדיר את מודל הידע; src/data בודק וטוען את התוכן ומסנן פריטים שאינם מפורסמים; src/app מציג בית, אטלס, קטגוריה ופריט. 12 הקטגוריות שומרות על מזהי 00–11. המקורות ותאריכי האימות נשמרים עם הפריט. תוכן Markdown וראיות מפורטות יותר יתווספו בהמשך. החלופות להלן נשמרות כרקע להחלטה.

## החלטת V1
Next.js + TypeScript (React) עם תוכן מקומי תחילה. אין צורך ב־API פנימי לקריאת קובצי התוכן. Supabase נדחה; Vercel מועמד לפריסה עתידית באישור נפרד. החלופות נשמרות כרקע להחלטה ולבחינה עם שינוי הדרישות.

### חלופות שיש להשוות
- Next.js עם תוכן Markdown/JSON סטטי תחילה ורק לאחר מכן Supabase.
- Next.js Frontend + ASP.NET Core API נפרד (אם יש הצדקה עסקית/תפעולית).
- Background Worker ב־TypeScript, C# או Python בשלבי העשרת הידע.
- פתרון חלופי ש־Codex מצא מתאים יותר על בסיס יתרונות וחסרונות מוכחים.

## גבולות מערכת לוגיים
1. **UI:** Home, Atlas, Category, Tool Details, Compare.
2. **Domain/Content:** Categories, Tools, Languages, Sources, Content Documents, Versions.

## מקור נתונים פעיל — 2026-11-02
מחליף את תיאור JSON כמקור האתר לעיל. Server Components → שכבת data אסינכרונית → getDatabaseCatalog → pg Pool → academy ב־Supabase. קטגוריות, entry_documents, catalog, מדידות ומדריכים נקראים בטרנזקציה עקבית לקריאה בלבד. תאריכי PostgreSQL מומרים למחרוזות לפני העברה לרכיבי Client. סודות וחיבור DB מוגנים ב־server-only; מידע של פריטים שאינם מפורסמים אינו מועבר ל־UI. אין מטמון בין בקשות ואין fallback לקבצים. כל נתיבי האתר דינמיים ב־Node.js; build אינו דורש חיבור למסד.
קבצי content וכלי research/metrics נשארים לצורכי היסטוריה ובדיקות, ואינם מקור האתר או תהליך פרסום למסד. טקסטי ממשק ועמוד הבית נשארים בקוד. טרם נוספו גיבוי חיצוני, audit או זהות DB מוגבלת; אין לבלבל read-only transaction עם הרשאות משתמש מוגבלות.
