## מסקנה והיקף

הפער העיקרי אינו מספר שרתי MCP אלא רצף לימודי: בקשת כלי עסקית → חוזה ואישור → פרוטוקול → SDK אחד → בדיקת שרת → אינטגרציה אמיתית. מומלצת הרחבת MCP הקיימת, הוספת יסודות ושישה מוצרים בעלי תפקידים שונים, ומדריך. אין צורך להוסיף SDK לכל שפה, כל connector או כל שרת מתוך directory.

נבדקו כיווני גילוי: SDK רשמי C# מול Python/TypeScript; transports/OAuth/discovery; Inspector ובדיקות CI; גישור OpenAPI ו־FastMCP; שרתים רשמיים ל־GitHub ולדפדפן; managed connectors/OAuth באמצעות Composio; Registry ושרתי reference. שתי חבילות חיפוש אינטרנט מרובות־שאילתות הובילו לפתיחת מסמכים רשמיים, repositories, licenses ו־releases. טענות להלן מבוססות על הדפים שנפתחו, לא snippets. נבדקו גם זהויות framework ב־02, מודלי07 ו־LiteLLM08 כדי לא לשכפל תפקידים. דוחות06–08 הקודמים הם היסטוריית אישור; אין בהם הוספות09 ממתינות המחייבות איחוד.

## פירוט מעשי והשוואות

**T09-01 MCP.** יש לשמר את הפרק, ה־slug וההשקה ההיסטורית. כיום הקטגוריה מסבירה Adapter וגבול הרשאות היטב; החסר הוא תצורת גרסה ומימוש מאומת. במפרט2026-07-28 בקשות יוזם הלקוח, ותשובות/notifications חוזרות מהשרת; metadata של גרסה ויכולות נשלחים לכל בקשה. STDIO הוא subprocess מקומי; Streamable HTTP משתמש ב־POST ובהחזרת JSON או SSE תלוי בקשה. אין ללמד session/stateful-init כברירת מחדל עדכנית או לטעון ש־SSE לבדו מתאר את כל ה־transport. [המפרט](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports).

Authorization אופציונלי בפרוטוקול בכללותו; כאשר הוא נתמך ב־HTTP מסמך האימות מגדיר מסלול OAuth/resource server. STDIO אמור להשתמש ב־credentials מהסביבה ולא באותו flow. זו עובדת מפרט ולא המלצה לחשוף שרת בלתי מוגן. יש ללמד scopes, audience, token passthrough/SSRF וגבול הרשאות גם אם SDK מציע אוטומציה. [Authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [security](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices). דוגמה מוצעת שלא הורצה: שרת `get_stock` מעל REST ארגוני; זהות המשתמש נבדקת בשרת השירות, לפני קריאת SQL. יתרון: לקוחות תואמים צורכים חוזה משותף; חסרון: גרסה, auth ומעטפת תפעול נוספים לחיבור ישיר.

**T09-02 יסודות.** דוגמה מוצעת שלא הורצה: המודל מבקש `reserve_item(itemId,quantity)`; ASP.NET מאמת DTO, הרשאת מחסן, כמות קיימת ו־idempotency key, ורק אז מבצע טרנזקציית SQL לאחר אישור. OpenAPI מתארת HTTP APIs ואינה פרוטוקול agent או מנגנון הרשאה; תמיכת importer ב־OpenAPI3.2.1 אינה נובעת מעצם קיום המפרט. [OpenAPI](https://spec.openapis.org/oas/v3.2.1.html). יתרון פרק עצמאי: אינו משכפל SDK או נעול לספק; חסרון: דורש מעבדה כדי להפוך ליכולת מעשית. `Microsoft.Extensions.AI` היא דוגמת מימוש .NET להפרדת interfaces/automatic tool invocation, לא הצעת רשומת framework נוספת בסבב זה. [Microsoft](https://learn.microsoft.com/en-us/dotnet/ai/microsoft-extensions-ai).

**T09-03 C# SDK.** פרויקט C# אמיתי עם APIs ללקוח/שרת, לא רק HTTP interoperability. התרשמות README כללית ״Apache2״ אינה מספקת: LICENSE מתאר מעבר MIT→Apache2, תיעוד CC-BY4, ותרומות קוד ישנות ללא הסכמת relicense נשארות MIT. יש לצטט את הקובץ המדויק, לא להסיק רישיון מ־GitHub `NOASSERTION`. [LICENSE](https://github.com/modelcontextprotocol/csharp-sdk/blob/main/LICENSE). דוגמה שלא הורצה: שרת ASP.NET חושף כלי stock עם DI ו־cancellation; לקוח .NET מבצע discovery ותוכנית בדיקות שגיאות. יתרון: שימוש במושגי .NET קיימים; חסרון: version negotiation ואבטחת האפליקציה נשארים באחריות המפתח. אין הבטחת שוויון תכונות לכל SDK.

**T09-04 Inspector.** core/client כתובים בסביבת JS/TS/Node; אפשר לבדוק שרת C# דרך הפרוטוקול, ואין כאן native SDK .NET. README v2 מציג Web/CLI/TUI, עם mcpdo experimental; קו v1 security-fixes-only. README דורש Node>=22.19 אך release2.13.0 ממליץ על runtime עם תיקוני אבטחה; יש להצמיד גרסת runtime ולקחת בחשבון שאישור `engines` אינו ראיית עדכניות אבטחה. [README](https://github.com/modelcontextprotocol/inspector), [release2.13.0](https://github.com/modelcontextprotocol/inspector/releases/tag/2.13.0). דוגמה שלא הורצה: בדיקת tools/list ו־tools/call, קלט לא תקין והרשאה חסרה, עם artifact תוצאה ל־CI. יתרון: אבחון דטרמיניסטי; חסרון: אחסון סודות/טוקנים דורש תשומת לב. רישוי במעבר בדומה ל־MCP/C#; לא לסמן MIT או Apache-only. [LICENSE](https://github.com/modelcontextprotocol/inspector/blob/main/LICENSE).

**T09-05 FastMCP.** Python core/API, לקוחות שפות אחרות דרך MCP; אין SDK C# של FastMCP מאומת. Apache2 לפי LICENSE. דוגמה שלא הורצה: לייצר אבטיפוס ממפרט OpenAPI של API מחסן ואז לצמצם לשני כלים עסקיים שנבחרו ידנית. יתרון: declarations פשוטים ו־OpenAPI bootstrap; חסרון: API רחב אוטומטי אינו בהכרח מתאים למודל. תיעוד FastMCP עצמו מזהיר מגישור אוטומטי של כל REST API; טענתו ליתרון ביצועים של כלים curated היא טענת ספק, לא benchmark שלנו. [OpenAPI integration](https://gofastmcp.com/integrations/openapi). SDK C# מתאים יותר לשירות .NET קיים; FastMCP מתאים כש־Python כבר חלק מהמערכת. אין להוסיף גם alias `jlowin` וגם `PrefectHQ`.

**T09-06 GitHub MCP Server.** מימוש Go במאגר הרשמי; צריכת MCP מכל SDK תואם אינה SDK C# מקומי של GitHub. MIT לקוד, תנאי GitHub והרשאות החשבון נפרדים. remote אינו זהה לכל יכולות local: התיעוד מונה גם כלים ייחודיים לשירות. דוגמה שלא הורצה: סיכום issues/PRs פתוחים בקריאה בלבד וב־toolsets מצומצמים, בלי כתיבת תגובה או merge. יתרון: אינטגרציה רשמית שימושית; חסרון: גישה לתוכן לא מהימן וסודות. read-only מסנן כלי כתיבה; lockdown הוא מסנן תוכן best-effort ואינו security boundary. [Configuration](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md), [remote](https://github.com/github/github-mcp-server/blob/main/docs/remote-server.md). אין לבלבל עם GitHub reference server המאורכב בתוך collection ההיסטורי. [reference servers](https://github.com/modelcontextprotocol/servers).

**T09-07 Playwright MCP.** שרת Node/TS בקוד Apache2; `codegen=csharp` אינו הוכחת מימוש השרת ב־C# או SDK .NET של חבילת MCP. דוגמה שלא הורצה: בדיקת workflow RTL ביישום React מבודד, זיהוי שדה חסר וצילום תוצאה, בלי שימוש בחשבון production. יתרון: גישור UI כשאין API; חסרון: תוכן עמוד, cookies ופעולות UI מגדילים את גבול האמון. README קובע שהשרת ואפשרויות origins אינם security boundary. עבור בדיקה חוזרת דטרמיניסטית יש לשקול Playwright test/CLI; אין להמיר כל E2E לפעולת מודל. [README](https://github.com/microsoft/playwright-mcp), [getting started](https://github.com/microsoft/playwright/blob/main/docs/src/getting-started-mcp.md).

**T09-08 Composio.** SDKs Python/TypeScript ו־MCP/HTTP הם המסלולים המאומתים; C# native רשמי לא אומת. זהות המשתמש והחיבורים מנוהלים דרך שירות, לכן MIT של SDK monorepo אינו רישיון לכל backend או היתר self-host. דוגמה שלא הורצה: אפליקציה מסכמת ללקוח issues מחשבון מחובר משלו, עם scopes מצומצמים ובידוד משתמשים; כתיבה מותנית באישור מפורש. יתרון: חוסך מימוש OAuth/refresh לכל חיבור; חסרון: אחזקת טוקנים אצל צד נוסף, חשבון/עלות ותלות בשירות. מספר אפליקציות נתמך באתר הוא טענת ספק ולא מספר משתמשים או הצלחת תרחישים. [Authentication](https://docs.composio.dev/docs/authentication), [SDKs](https://docs.composio.dev/docs/providers), [repo](https://github.com/ComposioHQ/composio). מחיר, SLA, אזורי אחסון וכל מסלול עיבוד לא נבדקו ולכן אין הבטחות בנושא.
