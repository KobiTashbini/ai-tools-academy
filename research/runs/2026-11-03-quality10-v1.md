## פירוט תיקון Langfuse ונקודות רגישות

הפרק הקיים נכון ברמת התפקיד וההבחנה בין tracing ל־evals; אין צורך למחוק את חמשת הסעיפים או להחליף slug. יש להוסיף תיקונים אחרי הסעיפים הקיימים, להרחיב דוגמה/תרגיל/חלופות ולעדכן מקורות ושפות. רשימת SDK הרשמית כוללת Python ו־JS/TS; יש מסלול OTel לשפות אחרות, ולכן C# אינו ״SDK Langfuse רשמי״. מקור ה־SDK מציין מינימום self-host4.59.0 ל־Pythonv5/JSv6; אין להציג התאמה לשרתv3 בלי שימוש בגרסאות SDK קודמות לפי המטריצה. [מקור תאימות](https://langfuse.com/docs/observability/sdk/overview).

[מטריצת התאימות הרשמית](https://langfuse.com/docs/compatibility) נפתחה גם היא ומצליבה serverv4GA/SDKv5-v6. ל־Cloud מצוין שינוי מתוכנן ב־16/11/2026: `/api/public/ingestion` יפסיק לקלוט tracing, עם חריג scores. זהו מועד עתידי ביחס למחקר, **לא הפסקת Langfuse ולא הוכחה שכבר נסגר**. למימוש חדש יש להשתמש ב־OTLP/HTTP endpoint המתועד ולהקפיד על header/mapping/context. קיימת אי־אחידות: דף migration עדיין מפנה למסלולי SDKv4/v5 הישנים, בעוד overview מתקדם ל־v5/v6; להעדיף compatibility matrix ולא להעתיק snippet מתיעוד ישן. [Migration](https://langfuse.com/integrations/native/opentelemetry/migration-to-v4).

MIT של הליבה אינו מכסה אוטומטית תיקיות Enterprise. server-side masking, retention policies, audit logs ו־project RBAC מנויות כיכולות EE; לכן בסביבת OSS צריך לתכנן השחרה ביישום לפני יציאה, ולא להבטיח בקרה שאינה במהדורה. self-host אינו ״אפס תחזוקה״: אחסון traces, גיבוי, גישה, נפח ומידע שנשלח לשופטי LLM דורשים החלטה. [EE license key](https://langfuse.com/self-hosting/license-key).

## דוגמאות ותרגילים מוצעים שלא הורצו

- **יסודות:** קחו20 בקשות ציוד, לרבות בקשה עמומה, מידע חסר ותוכן חיצוני שמנסה לשנות הרשאות. הגדירו expected outcome, פריטי מידע אסורים לפליטה וקריטריוני review; הפרידו correctness, latency, cost ו־authorization.
- **Langfuse:** trace של בקשת רכש: אחזור נוהל → קריאת מודל → הצעת כלי. השחירו מזהים לפני export; הפכו כשל אחד לדוגמת regression. בדקו שורש וילדים ואל תצלמו מפתחות/מסמכים מלאים כברירת מחדל.
- **OTel:** ASP.NET Core יוצר Activity סביב retrieval, HTTP model call וקריאת SQL; מזהה trace קושר תוצאה לכשל בלי להפוך metadata להרשאה. תכננו exporter אחד ויעד אחד, לא השוואת latency שהמערכת לא מדדה.
- **Microsoft Evaluation:** xUnit בוחן DTO, הפניה למקור והימנעות מפעולת כתיבה; הוסיפו Groundedness/Relevance על dataset עם human labels. תעדו model judge, prompt version, cache, קלט ועלות; score אינו שער הרשאות.
- **Promptfoo:** CI פונה ל־endpoint של יישום .NET עם fixtures סינתטיים; assertions לסכמה, סירוב עקיפת tenant ו־tool arguments. redteam רק מול יעד מורשה ובתצורת egress ידועה.
- **Ragas:** השוו שני chunking/retrieval setups מאותם מסמכי נוהל, בדקו relevance/faithfulness בנפרד והצליבו מדגם ידני. .NET מייצאת דוגמאות לתהליך Python; אין צורך לכתוב מחדש את השרת.
- **LangSmith:** אותו dataset של Langfuse באפיק ניסוי נפרד, עם הערכה אנושית וקוד לפני online judge; בחרו מסלול רק אם נדרשות תכונות/פריסה שמתאימות לארגון.
- **Phoenix:** בחנו trace של תשובה עם ציטוט שגוי והמרתה לניסוי על שני retrievers; בדקו רישוי לפני תכנון מוצר מבוסס Phoenix כשירות.
- **NeMo Guardrails:** הגדירו rail לנושא השיחה ולטיפול בקלט; הציבו הרשאת כתיבת SQL בשירות.NET מחוץ ל־LLM, ובדקו false positive/negative. שמרו fallback שאינו מבצע פעולה כשאין verdict ברור.

## מועמדים שנדחו או נשארו להמשך

- **DeepEval:** מאגר `confident-ai/deepeval` שנפתח מציג Python-oriented unit testing, מדדיLLM ותוספות agent. הוא חלופה לגיטימית ל־Ragas/Promptfoo, לא ״חסר חשיבות״; נדחה כרגע לצמצום חפיפה ולשמירת מסלול.NET ברור. אין טענת C# SDK ייעודי מאומת. [repo](https://github.com/confident-ai/deepeval).
- **MLflow:** תיעוד רשמי שנפתח מציג GenAI evaluations/monitoring ותהליכי tracing. המוצר אינו קיים בבסיס; מומלץ לחקור לעומק במסגרת11/MLOps ולשקול שיוך10 באותה רשומה בעתיד, ללא כפילות. סקירת רישוי/שפות/פריסה מקיפה שלו לא הושלמה כאן. [FAQ](https://mlflow.org/docs/latest/genai/eval-monitor/faq/).

## מדדים, טריות, ביקורת וגבול אישור

צילום Langfuse הקיים הוא31/10/2026 וכולל36,782 Stars; אין להציג אותו כמדידה חדשה. הסוכן הראשי אסף [צילום GitHub מרכזי](../evidence/integrations0910-github-2026-11-03.json) ו־[צילום OTel.NET ממוקד](../evidence/integrations0910-otel-github-2026-11-03.json), עם canonical redirect, Stars/Forks/archived/default branch/head SHA/date ו־release metadata; המספרים משויכים לתאריך האיסוף שלהם בלבד. אין איסוף כפול, סיכום Stars בין מאגרים, מדגם Interest חדש או סקר שימוש מאומת לקטגוריה זו. ל־LangSmith אין לייחס Stars של SDK כאימוץ מוצר, ולחבילות Microsoft אין לייחס Stars של monorepo/sample כמדד החבילה. ל־OTel .NET repo נדרש scope מייצג SDK.NET בלבד, לא כל הפרויקט. מושגי יסוד ללא מאגר מייצג.

ימי השקה ראשונים של המועמדים ו־Langfuse לא הושלמו במחקר זה; יישארו חסרים אלא אם יאומתו בנפרד. גרסאות שחרור ופעילות אינן הבטחת יציבות או אבטחה. לא נמצאה הצדקה מאומתת לסמן מועמד או Langfuse Legacy/Maintenance/Discontinued; אין להסיק הפסקה ממעבר SDK/endpoint או מרישיון source-available.

הביקורת העצמאית התריעה על Langfuse SDK/server compatibility, עתידיות שינוי ingestion, OTLP/HTTP והבחנת EE masking; אלה שולבו. הסוכן הראשי ירכז את השלמת הביקורת, מדידות המאגר וסתירות נוספות. מקור רשמי יחיד תומך בעובדה צרה; שני מסמכים של אותו ספק אינם אישור צד שלישי ליעילות. אין הבטחת״zero latency״או״cannot break app״מתוך marketing. גישה ל־OTel.NET overview נכשלה אך מדריך instrumentation נפתח; כתובת migration מנוחשת ו־NeMo LICENSE בלי suffix נכשלו, והוחלפו בקישורים ממשיים מהתיעוד. דף Microsoft Learn כלל הודעת authorization בכותרת אך גוף המדריך נגיש, והצלבה נעשתה עם NuGet הרשמי.

**לא שונה תוכן הקטלוג, סדר הלימוד, מקורות פעילים, מדדים, סכימה או קוד; לא בוצעו Commit/Push/Deployment.** ההצעות נמצאות בדוח בלבד משום שחבילת תוכן/מדריך ותיקונים מרובים אינם מיוצגים היטב בארבעת kinds של התור הישן. `research:check` הישן בודק35 seed entries ואינו הוכחת כיסוי71 הזהויות החיות. לא שונה validator או proposals.json.

לאישור: **quality10-20261103-v1 / Q10-01–Q10-10**, או תת־קבוצה. שינוי עדיפות Langfuse יכול להידחות בנפרד מתיקון העובדות; הכל נשאר pending_review עד החלטת המשתמש.
